# Browser iOS Lab

> [!note] 現在地
> ジャストアイデア。技術・市場・採算・Apple のライセンス条件は未検証。

## 概要

クラウド上の Mac で本物の iOS Simulator を起動し、ブラウザからアプリの操作と確認ができるサービス。検証環境は利用後に自動削除し、利用者のローカル容量を消費しない。

## 体験

1. GitHub リポジトリまたはアプリのビルドを登録する
2. iPhone の機種と iOS バージョンを選ぶ
3. ブラウザ内に Simulator の画面を起動する
4. タップ、文字入力、ログ確認、スクリーンショット、画面録画を行う
5. 終了後に環境を自動削除する

## MVP

- 代表的な iPhone 2機種
- iOS バージョン2種類
- ブラウザからのタップと文字入力
- Xcode ビルドまたは GitHub Actions との連携
- ログ、スクリーンショット、録画の保存
- チームに共有できる確認用 URL

## 想定ユーザー

- Mac の空き容量が少ない個人開発者
- Windows 環境から iOS 表示を確認したい人
- 複数の iOS バージョンを検証する開発チーム
- 顧客やデザイナーへアプリを手軽に見せたい人

## 差別化と料金仮説

BrowserStack のような本格的なテスト基盤よりも、個人開発者向けの「すぐ起動・低価格・共有が簡単」を重視する。料金は月額料金と利用分数による従量課金の組み合わせを想定する。

## 技術仮説と主な課題

ブラウザだけで iOS を再現せず、クラウド上の Mac で iOS Simulator を動かし、その画面と入力をストリーミングする。主な課題は Mac の運用コスト、操作遅延、同時実行数、ビルド時間、Apple のライセンス条件。

## 役員会式ミニレビュー

### 議題

個人開発者向けの低価格なブラウザ型 iOS Simulator を、小さく検証する価値があるか。

### イーロン・マスク視点

Simulator の画面転送だけでは模倣されやすい。「リポジトリ登録から1分以内に共有 URL が開く」ほど起動体験を圧縮できるなら、ローカル環境構築を置き換える明確な価値になる。最大の技術課題は Mac 稼働率と遅延の両立。

### 孫正義視点

個人開発者を入口に、チーム検証、顧客レビュー、自動テストへ広げられる可能性がある。一方で、Mac の原価とライセンス制約を踏まえて十分な粗利が出るか、市場規模と合わせて要検証。

### 相互反論

- イーロン役から孫役へ: 将来のプラットフォーム構想より先に、1セッションの原価と起動速度を実測しなければ拡張性は判断できない。
- 孫役からイーロン役へ: 起動速度だけを磨いても支払い意思が弱ければ事業にならないため、技術検証と同時に顧客用途を絞る必要がある。

### 統合結論

- 判定: 小さく検証
- 次の一手: 再開時に、Apple の利用条件と Mac 1台あたりの同時実行数・想定分単価を調べ、成立条件を1枚にまとめる。
